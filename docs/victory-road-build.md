### What changed

1. **Capsule gone, one Ren.** `vr-art.js` no longer has `champion()` (the vector illustration) or `capsule()`; every Ren now comes from `ART.trainer()`, a canvas with the title screen's 22 × 34 pixel sprite (`drawTrainer`, unchanged), sized in whole pixels by CSS (`.tvb-ren`, `--px` set by container queries: 3–7× in the battle intro, 3–6× in the cinematic, 7× on the title). Send-outs are a short stepped pixel flash (`tvb-enter`), no projectile; the `throw` sound, `throwCapsule`, `.tvb-throw`/`.tvb-capsule` CSS are removed. The cinematic's 30 s line is now "Ren steps forward. The crowd is on its feet." The matchup preview has **no** Ren picture. Credits and `NOTICE.md` updated.
2. **Types everywhere, one chip.** `TVB.typeChip` / `typeRow` (shell) is the only chip: type name as text, its colour as a left bar on a dark chip (text never sits on the colour). Placed on catalog cards (top-left, above the sprite; DOM order after the name so screen readers say the name first), party slots (under the name), member editor (as before), team-pick cards in battle (top-left of all six, in each card's accessible name), under every HP bar on both sides, and in every VS preview row. Battle typing follows the engine's log: species types on switch-in (catalog incl. battle forms, so Megas and form changes update), `-start … typechange` / `typeadd` / `-transform` replace or add and mark the chips "changed" (dashed outline, title text). Nothing is inferred from move names; the protocol was not extended (the log already carries every public type change).
3. **Type search.** `VRCore.matches(entry, query, gen)`: a query that is exactly one of the 18 type names (any case, trimmed) shows only that type, dual types included, within the generation filter; anything else matches name / Dex number / form as before. Count reads "87 Fire-type shown", "16 Fire-type shown in Gen I"; empty results say so; placeholder "Search by name, number or type".
4. **Party moves panel** (builder, between the 2 × 3 grid and Edit members / Modifiers): one entry per real member in party order (number, name, species types, then each saved move with its move-type chip; members without moves say so). It follows add/remove/reorder/editor changes by uid; scrolls inside itself; each name opens that member in the editor. With Random moves on it says the saved moves are replaced for the battle only; with Random team on it says a hidden team battles and shows only the saved party — no random identity or move ever reaches the DOM before team preview.
5. **Random team = five fully evolved + one legendary/mythical.** `species.json` gains a fully-evolved flag (field 10), built by `build-catalog.mjs` from the engine's own `evos` data (Showdown keeps them per form: Meowth-Galar → Perrserker, Primeape → Annihilape, Basculin-White-Striped → Basculegion; single-stage species count; battle-only forms aren't in the pool). `rollTeam` builds two disjoint pools (fully evolved non-legendary/non-mythical; fully evolved legendary or mythical), samples by species then form, shuffles the six, and throws if a pool is short (no silent fallback). Policy choices: Ultra Beasts and Paradox Pokémon are ordinary picks (they aren't tagged legendary/mythical in the data); the special slot is fully evolved too, so Cosmog, Cosmoem, Kubfu and Type: Null never fill it. `battleLoadout` re-checks the six (`randomTeamProblem`), and the engine boundary enforces the same rule from its own data (`validateTeam(…, { randomTeam: true })`, `isFinal`), passed by the worker only as `rules.randomTeam === true`. Manual parties keep the one-legendary/mythical limit and any evolution stage. Modifier copy updated.
6. **Poison → Steel report: not reproduced.** Friend's report: Sneasler's Poison move one-shot Poison/Steel Revavroom. Findings: (a) the pinned chart and the Champions mod keep Steel immune to Poison (`data/typechart.ts` Steel: Poison 3; the mod's `direclaw` only changes the secondary chance to 30% and adds the slicing flag); (b) 400 seeded AI battles with Revavroom on the player's side: 24 Poison attacks aimed at it, **24 immune, 0 damage** — all from a Choice Scarf Garchomp locked into Poison Jab (Ren's AI never chose Dire Claw into it; its damage estimate already returns 0 for immunities); (c) fixed scenarios on the shipped bundle's simulator (no AI): Dire Claw, Gunk Shot and Poison Jab into Revavroom → `-immune`, HP unchanged, no status, no faint; Close Combat still damages it; (d) renderer audit: visible HP only ever changed from each line's own `-damage`, but the old pacing (~500 ms per move, 450 ms per hit, everything back to back) could make a partner's hit in the same turn read as the Poison move's. No engine defect found and no engine rule changed; the regressions stay. The friend's actual battle can't be replayed (no seed or log), so its cause is unconfirmed.
7. **Readable move-by-move playback.** `VRCore.beats(lines)` splits each log batch into one beat per action (move with all its consequences, switch-in, can't-move, Mega Evolution, end-of-turn effects as a `residual` beat, upkeep, turn) and `steps()` groups a spread move's direct hits; order is never changed (tested). `vr-battle.js` plays beats through one queue: "X used Y!" (900–1200 ms by length, target marked ▼), hits (bar and number count down together over 560 ms), effect lines (800–1500 ms by length), "No effect" / "Miss" labels over the Pokémon, faints, then a 320 ms gap before the next action. Indirect damage and heals start their line first, then the bar. `frame[data-busy]` is set while anything plays; menus only appear after the queue drains (requests, the cinematic and the result already waited for it). Every wait resolves on dispose, so close/quit/rematch leave nothing hanging. Reduced motion now keeps the reading time (only movement and flashing go). Clicking or Enter still skips a line.
8. **VS preview and arenas.** The preview is an original versus board: rays from hard-stop conic gradients (blue left, red right) split by a stepped seam, a pixel bolt SVG and "VS" in Press Start 2P, solid roster panels with six rows sharing the height (sprite drawn 144% of its cell, name, types), footer with rules/reward/notes and Enter battle. Under 640 px wide the rosters stack and the board scrolls. A hidden random team shows six "?" rows ("Revealed at team preview"). The battle arena is `ART.arena(phase)`, a 320 × 180 crisp-edged SVG: **court** (sky bands, clouds, stepped hills, tree line, fence, mown court stripes in perspective, painted lines; earth-rimmed platforms) and **stadium** (truss roof, four floodlight banks with beams, four tiers of seeded crowd that sway in two steps, amber/red LED barrier, dark floor with amber markings and edge glow; slate platforms with amber rims). One `phase` value on the frame drives backdrop, platforms and crowd; the cinematic's 10 s cue sets it to `stadium` (the overlay thins so the change shows), it stays through resumed turns and the result, and a rematch builds a new court. Sprites are about 20% larger (far slots `min(20.5cqw, 41cqh)`, near `min(25cqw, 52cqh)`; phones `30cqw/37cqw`), still pixelated in fixed squares, so large Megas can't outgrow their slot.

### Architecture

- **Portfolio side** (`ui-v2.js`): Insert cartridge (Projects card or Home extra) opens the window and paints the boot screen at once (pixelated favicon on a 20×20 canvas, real loading bar, log line). It loads `vr.css` and six scripts in order (0–40% of the bar), then hands over to the game (`VictoryRoad.start`). Script failure → in-screen Retry. ✕, scrim and Escape go through `VictoryRoad.beforeClose`, so a running battle confirms inside the game; closing calls `VictoryRoad.dispose` (battle worker terminated, audio context closed, timers/listeners removed, fetches aborted) and restores focus to the opener. Old `.pdos-cr-*` setup CSS removed; boot rules live in `ui-v2.css` so they paint before `vr.css`.
- **Game files** (`public/vr/`, all loaded only after Insert cartridge): `vr-core.js` (pure rules, shared with the tests), `vr-audio.js` (Web Audio: music/effects/crowd buses, manifest, 38 s score), `vr-art.js` (original SVG art), `vr-game.js` (shell: state machine, boot data, title, name, Settings, Credits, confirmations, Escape hierarchy, lifecycle), `vr-setup.js` (builder, member editor, modifiers, preview), `vr-battle.js` (battle, cinematic, result), `vr.css`.
- **State machine** (`vr-game.js` `TRANSITIONS`): closed → boot → title → name → builder ⇄ editor, builder/editor ⇄ modifiers → preview → battle (intro, battle, escalation, phase two and result inside it) → battle (rematch) | builder | title; preview → builder (Fix party). Illegal transitions are refused. Settings, Credits and confirmations are modal panels inside the screen. Escape: closes a panel → leaves a picker → goes back one screen/menu → (battle) asks to quit; only at the title does it close the window.
- **Data** (built by `scripts/vr/build-catalog.mjs` from the engine bundle itself plus the pinned Showdown checkout's learnsets and English text): `species.json` (base stats, legal abilities with descriptions, class L/M/U/P), `learnsets.json` (844-move catalog with type/category/power/accuracy/engine PP/priority/target/description; per-species legal move lists as base-36 gaps), `items.json` (399 held items with descriptions, who can hold them, kind). Rule for "legal": the species, an earlier evolution, or the form it extends learns it by any method in any generation (Showdown's `learnsetParent`), Smeargle can Sketch anything sketchable; Z-Moves, Max Moves and CAP/LGPE/custom/future moves excluded; event-only combinations are not cross-checked.
- **Draft vs battle loadout**: the party is `[{ uid, id, moves, item, ability }]` (stable `uid`, so moves/items follow the Pokémon through reorder/remove). Stored as `pdosTheVeryBest` v3 (filter, party, modifiers only — never the trainer name or a random team); `pdosVictoryRoad` v2 and `pdosChampionRun` saves migrate once. Every restored field is validated; anything illegal falls back to the default set; a second legendary/mythical is dropped with a note. Enter Battle copies the draft into `battleLoadout` and only then applies Random team / Random moves / Random held items, so the draft is never touched (tested byte-for-byte).
- **Item Clause and defaults**: default sets often share items, so a newcomer whose default item is taken gets the first free general-purpose item (`FALLBACK_ITEMS`). Random team and restore use the same rule.
- **Engine** (`scripts/vr/engine/*`, rebuilt into `vr-engine.js`, 356 KB gzipped): `validateTeam` at the boundary (2–6, Species Clause, one legendary/mythical by Showdown tags, 1–4 unique usable moves legal per `learnsets.json` — the worker fetches it itself — legal ability, item exists/holder/Item Clause, stat points ≤ 32 each and ≤ 66); request ids (`rqid`) so stale choices are ignored; the worker only accepts `start` once, `choose` with an allowlisted choice pattern and matching battle id, and `resume`. Separate seeded streams for the champion's configuration, its strategy, chaos replacements and the simulator.
- **Champion** (`champion.js`): species, forms, items, abilities, natures and stat points fixed; moves drawn per battle from versioned variants (`TEMPLATE_VERSION` 1; official set weighted highest) chosen to fit the fixed items (no status on the Scarf Garchomp, special attacks on the Modest Dragonite). Team rules: ≥ 2 Protect users and a tempo tool (priority, Fake Out or Tailwind). Every variant move is checked against the learnset in tests. Information policy: species shown at team preview; moves hidden until used; full sets revealed on the result screen.
- **AI** (`ai.js`): still information-limited (own request + public log view). New: both slots chosen together (every pair of the six best actions per slot scored as one turn: no overkill double-counting, KO bonus when two attacks combine, Helping Hand valued by the partner's damage), Protect prediction from public facts, Fake Out immunities (Inner Focus, Armor Tail, Queenly Majesty, Dazzling, Psychic Terrain), Tailwind and set-up timing, voluntary switching when threatened with nothing useful, Showdown fallback (`default`) on any error. Bounded to a few dozen pair evaluations per turn.
- **Championship escalation** (engine): once per battle, when two *different* participating champion Pokémon have fainted, at the next end-of-turn boundary (fresh move request, or the end-of-turn replacement request after residuals; never mid-turn) the battle pauses and emits `escalation`. No choice is accepted while paused; `resume(id)` (duplicates/wrong ids ignored) revives the first champion Pokémon to have fainted (`REVIVE_COUNT` = 1) at 50% max HP (rounded down; status cleared; PP and used items stay spent; boosts were cleared by fainting), increments `pokemonLeft`, logs `-heal … [from] vr: championship`, then re-issues fresh requests. A revived Pokémon still in its fainted slot is replaced as usual and goes back to the bench (Showdown runs switch-out events on it; none of the champion's abilities/items have any — tested). If the player is already out, the battle has ended and the loss stands. The record (`state().record`: seed, template version, variants, faints, escalation) replays deterministically.
- **Cinematic** (`vr-battle.js` `runEscalation`): a 38 s timeline on one clock — the AudioContext's when audio runs (so the unlock lands on the drop), else a performance clock that only advances while the tab is visible. Cues: 0 s respectful dialogue, 10 s arena lights, 14 s crowd rises (crowd audio), 22 s fire glow, 26 s final line, 30 s capsule charge, 36 s flash, 38 s resume + revival + finale music. Skip (button or Escape) seeks to the cue and runs the same once-only rule. Reduced motion keeps the timeline without movement. Background tabs suspend the audio context and the timeline together.
- **Audio** (`vr-audio.js`): master mute plus Music, Effects and Crowd levels (Settings, remembered per browser). Original synthesised menu loop (title → preview), battle loop, finale loop, 38 s build and drop, crowd, and navigation beeps on every menu. `AUDIO_MANIFEST` lists `menu`, `battle`, `escalation` (`resumeCueSeconds: 38`), `crowd` with the requested tracks recorded as **blocked** references; no Spotify integration.
- **Battle UI**: everything inside the frame — arena on top (keeps proportions via container units), dock below with the text box (prompt, move details, narration) and the command grid (Fight / Bag / Party / Quit, moves with type/PP and full details on focus, Mega toggle, targets with left/right/partner labels, "1 of 2" slot indicator and a highlighted platform for the Pokémon choosing, forced replacements per slot). Remaining-Pokémon indicators, original Ren illustration intro and a capsule throw for the first two send-outs. Result screen: reward, turn/KO summary, Ren's most-used moves, tips on defeat, Ren's full sets, Rematch / Edit party / Title.

## Phase 2 — battle engine and battle screen (2026-10-07)

- **Engine bundle:** `npm ci --prefix scripts/vr`, then `node scripts/vr/build-sim.mjs <showdown checkout>` (refuses any commit but `c046106c…`) writes `public/vr/vr-engine.js` (1.65 MB, **352 KB gzipped**), a Web Worker loaded only when a battle starts. - **AI** (`scripts/vr/engine/ai.js` + `view.js`): gets only its own request and a view rebuilt from its own log channel (opponent HP as %, only revealed moves and items). Scores every legal action by estimated damage (type chart, base stats, public boosts, STAB/Adaptability, spread ×0.75, Life Orb, Multiscale, Low Kick weight, Last Respects count), KO bonuses, first-turn Fake Out, Protect when low (never twice running), recoil penalties, and a partner-hit penalty for moves like Earthquake; picks among actions within 8 points using its own seeded RNG.
